# Plans

Notes for work that is not in the app yet. Michael Faulcon decides when a plan starts. Until then it stays here and the code stays as it is.

| Plan | Status |
| --- | --- |
| Keyboard grid | Shipped. Tab moves focus onto the step grid. The grid draws a high-contrast cursor on the current cell, at full opacity after the pad, so it stays visible over slide wedges, velocity shading, mute, and solo. Left and Right move one step and stop at the ends. The cursor does not wrap. Up and Down move between rows and stop at the first and last row. Ctrl+Up and Ctrl+Down do the same. Alt+Up and Alt+Down still reorder the row. Home and End jump to the first and last drawn step, including a step past the pattern length. Enter toggles the step under the cursor and Shift+Enter makes a loud hit, both through the same edit as a click, so undo, save, and playback match. Space still plays or stops while the grid has focus, because the grid is focused when the window opens and Space is the play key. G, nudge, and the Volume slider follow that cell. The grid is named Step grid, each row uses the track name, and the focused cell is named like "Kick, step 5 of 16, on, accent". A toggle announces the new name. Save format, MIDI, and WAV are unchanged. Still deferred: keys that raise or lower one step's velocity by a single value (Shift+Enter and the Volume slider are the ways to set it), and a pass with a running screen reader. Java Access Bridge is not started in CI. |
| UI polish (M11) | Shipped. Help → Keyboard Shortcuts (F1) lists every key and mouse gesture the window actually handles, including Space, T, G, M, S, comma and period, the Alt row keys, and Ctrl/⌘ Z and S. M mutes the selected row and S solos it. Tooltips name the controls, including those shortcuts. An empty pattern says to click a square and press Space. The first launch still starts on Boom bap until that hint is dismissed. The drum sound picker is one row tall instead of the height of the hidden sample form. Tempo reads as a BPM value, and the step count says steps. Load and export errors that used to quote the parser now say the file is damaged, incomplete, or from a newer Hits. Undo and redo already covered grid edits and row add, remove, and reorder, so that was left as it was. Save format, MIDI, and WAV are unchanged. Still deferred: rewriting the channel-pool warning (the window and `hits info` share that sentence); hover marks on every control; fractional tap tempo. |
| Compact inspector | Shipped. The row inspector groups Sound, Tone/Envelope, Filter & EQ, Slide, and Sample. Slide is shown only on a note or sample row, and Sample only on a sample row. Sound starts open. Until a header is opened or closed, a section opens when the selected row's settings differ from the defaults, and stays closed when they do not. A header that is doing something shows an active badge and a summary, such as "Filter & EQ: Low cut 80 Hz, 2 bands, High cut 5 kHz", and that summary stays visible when the section is collapsed. The summary is part of the header, so clicking it expands the section. Headers are in the Tab order. Enter or Space toggles the focused header, and Space still plays or stops everywhere else. Help → Keyboard Shortcuts lists that. The choice lasts for the session. Save format, MIDI, and WAV are unchanged. Still deferred: storing which sections are open in a preference file, and a pass with a running screen reader. Java Access Bridge is not started in CI. |
| More tracks | Shipped. A beat has 1 to 16 rows, the same count in every pattern. Add, remove, duplicate, and reorder apply to the pattern grid and the mixer. A new row fills a missing kit piece, Kick first, then a 46 Hz sine named Sub when the beat does not already have one, then an empty drum. The count is the length of each `tracks` array, so an eight-row file still writes the same bytes. Rows that send the same instrument, pan, tune, decay, and effects share a MIDI channel once the 15 non-drum channels are full. Melodic rows that do not overlap in time share a channel with a program change. A melodic row is never put on channel 10. When it overlaps every free channel, the MIDI file leaves it out and WAV export plays it on a second synth. `hits info`, `hits render`, and the window name a real conflict. Still deferred: more than 16 rows, a different row count per pattern, live playback and external MIDI of that overlapping melodic row (WAV already plays it), sharing the extra channel a filtered-and-plain row needs, the metronome staying on channel 16 while a full pool also uses it during playback (exports leave the click out), cutoff and decay on an overflow drum (the GS per-key messages still carry tune, reverb, and chorus only), and `.btf`, which is still the 2001 8×16 file. |
| [Sample tracks](sample-tracks.md) | One-shots shipped. Still deferred: one sample per row across patterns, stereo, loops, embedding the SoundFont in the MIDI file, and external-output playback of the WAV. |
| Bounded sample load | Shipped. A sample is decoded only up to 10 seconds at the file's own rate and channel count, then downmixed the same way as before. A longer file is cut at that cap, and the samples kept match a full read of a file that already fit. The loader refuses an empty file, a file over 512 MB, a header whose audio length is zero, negative, or far too long, a format Hits cannot play, or a file that ends before the header's audio. The inspector, `hits info`, and `hits render` say so in plain language, and the row plays its drum note. A read that takes more than 5 seconds is abandoned. The bytes actually read are also capped (64 MB), which is more than 10 seconds of a normal recording. Still deferred: streaming the first 10 seconds of a file over 512 MB (those files are refused), and formats the JDK cannot decode, such as MP3 or FLAC. |
| [Live input](live-input.md) | On hold until Michael is ready. Computer-keyboard step entry, live recording, and MIDI controller input. |
| Cutoff ramp | Not in the app. Per-slot cutoff already filters one pattern and leaves the next open. A linear `cutoffTo` across a pattern is still deferred. |
| CC 75 decay | Not sent. On the built-in synth it collapses an open hat below the neutral value and does not move a kick, tom, saw, or xylophone. Decay is CC 72. |
| Low-cut velocity curve | A filtered drum or note is recorded at velocity 100 and replayed from the sample bank. EQ uses that same recording. Other velocities follow the SoundFont curve, which is not the General MIDI drum curve. A GM kick at low cut 20 Hz now matches the unfiltered kick within 0.5 dB at velocities 80, 100, and 127. Other drums and notes are not checked that way. |
| Per-step low cut | Low cut, presence, and EQ are per row, and can differ between patterns on that row. A step does not have its own corner or its own bands. |
| More than three EQ bands | A row keeps the first three bands, in the order they are written. A later band is dropped on load. `hits info` and the inspector name each dropped band, including a low shelf or a high shelf. |
| High-cut shelf | High cut is a Butterworth low-pass at 6, 12, or 24 dB/oct. 12 is the default and is left out of the file. A high-cut shelf is still not offered. |
| Held-note low cut | Shipped for level, loop, and release. A filtered note loops a short crossfaded slice of the steady sustain and keeps the recorded tail after note-off, about as long as the unfiltered note. It is still not the live oscillator. |
| Pitch slides | Shipped for note rows and sample rows, including Sub. A slide step holds the previous note and bends to its own pitch. There is no new attack. Slide time is 10–500 ms, 80 ms when the file leaves it out. The curve is linear or exponential in pitch. The bend is MIDI pitch bend after RPN 0, wide enough for the largest interval on that row and never wider than ±24 semitones. A sliding row does not share a channel. A drum row does not keep a per-step slide flag (X1). Still deferred: a slide-to interval on a drum row, a glide farther than ±24 semitones (the bend stops at the edge), and a sample that failed to load (it plays on the drum channel, and a bend there would move every drum). |
| Fractional tempo (M2) | Shipped. Tempo is stored in hundredths of a BPM, from 40 to 240, so 92.5 and 98.33 are exact. The spinner still steps by 1 with the arrows, and the field accepts a decimal. A whole number is written as an integer, so an old file loads and saves the same bytes and renders the same MIDI and WAV. MIDI tempo is microseconds per quarter, rounded to the nearest microsecond, except a whole-number tempo keeps the earlier truncating division. Step times come from the absolute tick. WAV sample positions come from that tick and the exact tempo, so a long song does not drift by summing rounded steps. A 92.5 BPM, 64-bar song ends within 1 sample in the WAV and within 1 tick in the MIDI file. Still deferred: tap tempo still lands on a whole number, a pattern does not have its own tempo, and `.btf` is still 120. |
| Drum slide flag (X1) | Shipped. Ctrl-click, G, and the Slide checkbox do nothing on a drum row, and the grid does not draw the slide wedge there. Loading or saving drops a per-step slide flag on a drum and leaves every other field. A note row and a sample row, including Sub, still glide. Still deferred: a slide-to interval on a drum row. |
| Sample gain migration | Not implemented. Version 2 cannot tell a pre-#23 sample beat apart from a current one: an omitted `gain` used to mean 0 dB and now means +8 dB. A future version 3 would mean omitted gain is +8. Loading a version 2 file that has sample rows and omits `gain` would write explicit `"gain": 0` so those beats keep the quieter level. Do not change beats that already store `gain`, and do not change version 2 files that have no sample rows. Do not change the bytes of a beat that uses none of the newer fields. |
